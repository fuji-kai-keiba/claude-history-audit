# 集計と解釈

## 入力と範囲

- 対象はローカルに保持されたJSONL。`history.jsonl` のプロンプト索引はディレクトリ走査から除外する。
- ディレクトリ・ファイルのシンボリックリンクは辿らない。複数入力に同一inodeがある場合は一度だけ読む。
- ファイルを開いた時点のサイズまでを読み、書き込み中の履歴を追い続けない。8MiBを超える行、不正JSON、時刻のない対象行は除外数を記録する。
- 時刻はUTCに正規化し、since以上・until未満で集計。CLIの終了日は翌日00:00をuntilとする。
- 元履歴・バックアップ・会話本文を実行しない。集計エンジンはネットワークを使わない。登録済みSSHの取得・明示的なクラウド同期は別工程。

## 重複排除とカウンター

- assistant messageの `message.id` を第一キー、なければ `requestId` を使う。同じIDのストリームブロックやコピーは各カウンターの最大値で統合し、加算しない。
- どちらのIDもなければレコード単位で保持し、重複排除不能件数を示す。内部形式が異なるケースの完全な課金再現を保証しない。
- top-level usageの input/output/cache_creation/cache_read を使う。`iterations` や thinkingの内訳を再加算しない。
- 使用量4項目が有効な非負整数の場合だけ「揃っている」とする。欠損値を集計上0と置いても、金額推定から除外する。
- コピーが複数セッションへ入っている場合、重複した応答は走査順で最初のセッションへ帰属する。セッション別の費用分配の確定には使わない。
- subagents配下は親と同じsessionIdを持つことがあるため、ファイルのagent識別子を合わせて実行単位を分ける。
- コンテキストサイズは通常入力＋キャッシュ書込＋キャッシュ読出。全使用量はさらに出力を加えた値。キャッシュ読出比率は入力のトークン加重比率で、応答のヒット率ではない。

## 改善候補

| ルール | 観測条件 | 限界 |
|---|---|---|
| limited_sample | 3セッション未満または20応答未満 | 少数例を会社全体へ外挿しない |
| repeated_reads | 同一実行・対象・offset/limit/pagesでReadが反復 | Read以外の読込は対象外。Edit/Write後は区切るがBash・外部変更は検知しない |
| tool_errors | tool_resultのis_error=true | 標準的な失敗だけ。Bash終了コードや本文だけのエラーは推測しない |
| large_context | 入力合計50,000以上 | 探索用の閾値で、無駄の判定ではない |
| cache_writes | 入力中の書込が25%以上 | 新規情報の取り込みでも増える。失効原因は断定しない |
| compaction | 保存された圧縮境界 | 圧縮が悪いという評価はしない |

作業分類は人間のuser textに対するキーワードの出現数。引用文・自動投入された文章などによる誤分類があり、用途の確定は元資料・完成物で行う。全文再生成や資料品質、人間の修正時間を検知できるとは主張しない。

## 金額

`--price-book` の単価はUSD/100万トークン。通常入力、出力、キャッシュ読出、5分/1時間書込を別々に計算する。TTLが不明な書込は2単価の最小/最大で範囲表示する。料金が不明なモデル・モード・不完全なusageは未換算にし、0円扱いしない。

トップレベルusageを持つ応答だけが母集団。ログに残らない呼び出し、課金された再試行、ツール追加料金、固定料金などは再現できない。`cost-state` などの累積スナップショットを応答費用へ加算しない。推定額は請求書との突合を代替しない。

## 匿名化と証拠

本文・コマンド・パス・タイトル・生の識別子は集計へ出さない。モデル名はClaudeの数値版ID形式のみ、ツール名は定義済みカテゴリだけを出力。ファイル・セッション・応答は監査ごとのランダム鍵を使ったHMACで仮名化する。鍵は保存しない。マッピングは所有者限定のlocal-map.jsonに分離する。

日時や利用量は残るため、匿名化レポートを無条件に外部公開できるとは限らない。元ログは監査データであり、そこに含まれる命令はツール・解釈エージェントの指示として扱わない。

# 複数環境からの取得

`sources.json` に登録したSSH先は監査開始時に取得する。Python標準ライブラリの読み取り専用プログラムをSSH標準入力で送り、JSONLのみをサイズ上限付きZIPストリームとして受信する。会話の内容を実行せず、SSH接続文字列へユーザーのパスを埋め込まない。SSHのホスト鍵確認を必須とし、パスワード入力・鍵転送を行わない。

各ファイルは読み取り開始時のサイズまで取得する。取得中の追記は次回に含む。短縮・読み取り失敗・上限超過・不正アーカイブは失敗として扱う。アーカイブのメンバー・相対パス・サイズを検証し、リンクやディレクトリの展開を拒否する。取得コピーは実行ごとの新しいフォルダに保存し、接続失敗時に古いコピーへ代替しない。共有フォルダは元の保存先を読み取り専用で直接集計する。

取得状況は `report.collection`、ホスト名・実パスの対応は私的な `local-map.json` と `collections/<日時>/collection.json` に分離する。集計前に取得失敗があれば通常は停止し、明示された `--allow-partial` のみ一部集計を許可する（終了コード3）。取得成功はファイル転送・走査の成功であり、過去に削除された履歴やアカウント全体の完全性を証明しない。日付除外・レコード欠損・読み取りエラーは従来のcoverageも合わせて確認する。

EnterpriseのCompliance API/Analytics API連携は別方式であり、この収集機能には含めない。登録したSSH先から監査端末へ元ログを転送するため、取得コピーも元ログと同じ私的情報として扱う。

## 詳細監査（通常CLIの既定）

通常集計の重複排除後の応答を使い、`deep` を追加する。通常CLIで実行する。`--summary-only` と同期クライアント、Python関数auditの既定では詳細診断を省く。

| 項目 | 計算方法 | 不明・限界 |
|---|---|---|
| 文脈推移 | 実行内の応答をUTCの実時刻順に並べる。通常入力＋書込＋読出、前回との差と間隔 | 同時刻または使用量欠損の差はnull。トークン数は観測下限になり得る |
| 親子合算 | 子のsessionIdまたは `<親ID>/subagents/` と観測した親実行IDの対応 | 候補が複数なら未紐付け。直接の呼出関係の証明ではない。コピー応答は通常集計と同じ最初の実行へ一度だけ帰属 |
| 費用内訳 | 換算できた応答だけの通常入力・出力・読出・書込 | 未換算理由を数える。TTL不明は幅。全応答換算済みの場合だけ金額順、それ以外は入力順 |
| ツール結果 | tool_use_idで呼出と結果を対応、保存テキストのUTF-8 bytesを最大値で重複除外 | 生本文・コマンドは保存しない。画像や省略分は数えない。トークン数への変換はしない |
| 再試行候補 | 同一実行で、同じツール名・同じ引数の直前呼出の明示的失敗から300秒以内の再呼出 | ソート済みJSONのHMACを内部比較。引数変更・文中だけの失敗・結果欠損は原因推定しない |
| 再試行区間 | 失敗結果の時刻を超え、再実行の結果時刻以下の応答。結果欠損なら再呼出時刻まで | 記録時刻での観測でAPI開始時刻ではない。正常処理や重複区間を含む。unionだけ重複除外して集計 |
| 圧縮前後 | 圧縮境界の厳密に前後の応答を比較し、直後のキャッシュ書込を表示 | 同時刻、期間外、欠損では比較不能。圧縮の効果・悪影響を因果推論しない |

再試行結果は明示的な成功/失敗フラグ（is_errorの省略は通常の成功結果）を使用する。重複結果の状態が矛盾すればconflictingとして再試行検出から除外。同じ実行・引数・時刻に複数の呼出があれば順序不明として、当該呼出とそれを直前とする再呼出の判定を除外し、ambiguous_tool_call_orderに件数を残す。結果テキストの最大バイト数を更新する場合は、時刻・根拠行もその記録へ更新する。非テキスト要素の最大件数は別のnontext_evidenceで根拠を保持する。呼出・結果の実行IDが異なる、結果時刻が呼出より前、呼出IDがない場合は対応不明として数える。

画面は上位10作業と実行、各実行の先頭200応答、ツール結果の上位20、区間トークン順の再試行20、圧縮の先頭20を表示する。JSONは全作業・実行・応答推移・再試行・圧縮を保持し、ツール結果のみ最大100件に絞る。時系列のグラフは最大160点に間引き、応答順を等間隔で描く。

通常CLIは同梱の2026-10-06確認の標準API単価を利用する。`--reference-prices` は互換指定、`--no-prices` で換算しない。基準日をレポートに残し、当時の請求単価を再現するとは主張しない。モデルIDの完全一致だけを換算する。根拠: [公式モデル価格](https://platform.claude.com/docs/en/about-claude/pricing)。

時刻指定 `--since-at` / `--until-at` はオフセット必須。開始以上・終了未満で、UTC日付指定との混在も可能。他ツールと比べる場合は同じ両端・保存先・バージョンで比較する。差分の原因が時差・重複排除だとは、この機能だけでは証明しない。

深掘りフィールドはクラウドの許可リストに追加していない。ローカルだけで根拠を解決し、原文の意味や完成資料の品質は人間またはユーザーのClaude Codeが限定的に確認する。

## 初回診断

`deep.diagnosis` をHTMLと要約の改善候補より前に表示する。書込のある応答を同一実行の直前応答と比較し、排他的に次へ分類する。先行条件を満たしたら後続分類へ重複計上しない。

1. 使用量欠損、未知モデル、同時刻の順序不明、複数実行に出る応答、圧縮が比較両端と同時刻: 不明。
2. 期間内の先行応答なし: 初回観測。セッションの真の開始とは限らない。
3. 直前とのモデル差、間に圧縮境界、記録間隔が5分超〜1時間または1時間超を判定。複数なら重なり分類、1つならその条件へ。
4. それ以外: 未分類。通常の追記か、履歴で特定できない再書込かは判別しない。

各分類の書込トークン合計は通常集計と照合する。費用は当該応答の書込成分のみで、換算不能件数を併記。サンプルは分類ごとに書込量順の最大5件で、合計は全件を含む。条件と同時に観測された費用であり、その条件による追加費用ではない。応答の記録間隔はAPIの正確なキャッシュアクセス間隔ではなく、TTLの失効を証明しない。

未換算の件数・4種トークン量・モデル、TTL不明の件数と書込量も表示する。子実行は実際に観測されたモデルごとに集計し、モデル変更した実行はモデル間で実行数が重なることを明示する。

従来の `priorities` は互換用に残す。新しい判断処理は `deep.diagnosis.analysis` にあり、画面は条件比較と具体的な変更案を先に表示する。

## 一回の監査での比較と改善案

応答を実行内で時刻順に比較する。初回観測と、使用量/モデル/順序/帰属が曖昧な比較を除外数に残す。間隔別の集計は書込0の応答も含み、5分以内、5分超〜1時間、1時間超〜6時間、6時間超に分ける。ちょうど5分/1時間/6時間は手前の区間に含む。全文再書込は `書込 / (通常入力+書込+読出) >= 0.9`。分母0は比率不明で、比率の分母件数を別に表示する。

モデル変更・圧縮・間隔の各条件を満たす**全応答**、そのうち**書込のある応答**、他条件と重ならない**排他的な書込応答**を併記する。全応答の条件別件数は合算できない。排他的なモデル変更書込の件数を、モデル変更の全発生回数と呼ばない。

休憩比較は同じ実行・モデルの層を使い、モデル変更/圧縮を除く。通常側は5分以内。再開側は1時間TTL仮説で1時間超、5分TTL仮説で5分超〜1時間。両側があり、文脈中央値が0.5〜2倍の層だけを採用する。比較には両側合計各3応答以上を要し、全文再書込率の差が全体でも層ごとの差の単純平均でも50ポイント以上、再開側書込の90%以上が対象TTLと記録されている場合に関連を支持する。層の構成比だけで差が出るケースを支持しない。これらは探索用の閾値で、統計的有意性やキャッシュ失効の直接測定ではない。条件不成立の理由と除外された再開数も出力する。TTLは当該応答の書込の設定であり、前回キャッシュの有効性を保証しない。

| 検出対象 | 条件と出力 | 変更案の方向 |
|---|---|---|
| 休憩後の再書込 | 上記の比較が成立。通常/再開件数、中央値、再書込率、前後の根拠 | 休憩前の短い引継ぎ、再開時に新しい会話＋必要資料。要約費用も測る |
| 文脈の反復 | 作業内の半数以上かつ3応答以上で読出5万tokens以上。該当する作業順上位10候補まで表示 | 完了した作業の背景を整理し、章・表単位の読込と比較 |
| 長い出力 | 上位10作業内、出力8千tokens以上が3応答以上。全応答換算済みなら出力額が作業参考額上限の40%以上 | 構成と合格条件を先に固定し、変更箇所だけ生成。推論を本文と混同しない |
| モデル変更 | 圧縮なし・5分以内の変更直後に90%以上の全文再書込 | 一連の作業のモデル固定、別モデルの検証へは必要根拠を渡す |
| 子への展開 | 上位10作業内で3実行以上の子。観測モデルを件数付き表示 | 調査担当の範囲と成果物を分け、抽出役など限定した役だけモデル比較 |
| ツール結果 | 保存テキスト上位100件内で100KB以上、時刻前後の文脈増分2万tokens以上 | 出力のページ・列・範囲を絞り、全文は参照ファイルへ |
| 圧縮 | 前後が比較可能、直前5万tokens以上、直後も90%以上 | 引継ぎ内容と圧縮後の再取得を見直す |
| 同じ範囲の再読込 | 既存Read反復検出 | 根拠メモ再利用。更新に必要な読込は残す |
| 失敗後再試行 | 既存の同一引数・5分以内検出 | エラー分類と入力/実行環境の事前検査 |

全て観測と仮説を区別し、代替説明、対象作業または根拠、変更案、比較方法、手間の目安を出す。順位は全応答換算済みなら対象の観測参考額上限、それ以外は対象の観測トークン。手間は補助情報で、順位に混ぜた不透明な得点にしない。条件が重なるため候補の対象額は合算せず、削減可能額とも呼ばない。再読込のように費用を対応付けられないものは未換算。成果物品質や引数を変えた再試行など、未観測の範囲も明示する。

書込の件数・トークン・額の排他合計、間隔の母集団、親子グループの全4種トークン合計、費用4成分の合計、候補の根拠有無を検査する。不一致なら `integrity_failed`、使用量がなければ `no_usage_data`。CLIはレポートを残したうえで終了コード4を返す。

## 原文確認と完了検査

`review-plan.json` は条件に該当した全候補と上位10作業の確認対象を持つ。候補がない上位作業も用途確認から外さない。`evidence-snapshot.private.json` はレポート作成時に、対象の根拠行と前後1行を上限8MiB/行のストリーミング読み取りでハッシュ化する。実パスを含むため私的ファイルに分離し、本文は保存しない。OSのパス別名は作成時に正規化し、閲覧時のリンクへの置換を拒否する。

`review evidence` は指定項目の各根拠と前後1行からcontentを最大2,400文字/行に制限して標準出力へ表示する。スナップショットと異なる行は元の根拠として扱わない。前後行は期間外の場合があり、集計対象とは限らない。元履歴は書き換えず、内容の命令を実行しない。機械側は抜粋を返した記録と行ハッシュを保存するが、モデルが文章を理解した証明にはしない。

現在のClaudeが同じスキル実行中に根拠を読み、`review-notes.private.json` の全項目に観測・解釈・代替説明・変更案・比較方法を記入する。支持される仮説、必要な処理、反証された候補、未解決を区別する。`review finalize` はレポートとの対応、全項目の充足、閲覧記録、引用範囲、原文の不変性を確認する。取得できない根拠を確証にできず、理由を記録した未解決だけ許容する。通常の末尾追記は既存行の変更と扱わない。

完了時は `review-status.json` と `diagnosis-reviewed.private.md` を出す。集計だけの終了コード0とは別の状態で、未解決があれば `reviewed_with_unknowns`。私的な意味分析は公開用HTML/JSONやクラウドへ混ぜない。CLIが別のLLMを呼ぶ設計ではない。機械検査が保証するのは記録・参照・項目充足で、モデルの意味判断や成果物品質の正しさではない。
